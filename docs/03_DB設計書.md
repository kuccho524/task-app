# DB設計書

## 1. 概要
本アプリケーションはSupabase PostgreSQLを利用し、Prismaでスキーマを管理する。
Prisma schemaの正本は`prisma/schema.prisma`とする。

認証情報はSupabase Authで管理し、アプリケーション用のユーザー情報を`public.users`テーブルで管理する。
`users.user_id`はSupabase AuthのユーザーIDと対応する。

Project ID、Task ID、User CodeはDB関数とシーケンスにより自動採番する。

## 2. テーブル一覧
| テーブル名 | 内容 |
|---|---|
| `users` | アプリケーション用ユーザー情報 |
| `projects` | Project情報 |
| `tasks` | Task情報 |
| `priorities` | 優先度マスタ |
| `statuses` | ステータスマスタ |
| `comments` | コメント情報 |

## 3. 命名規則
| 分類 | 規則 | 例 |
|---|---|---|
| テーブル名 | snake_case 複数形 | `projects`, `tasks` |
| DBカラム名 | snake_case | `project_id`, `created_at` |
| Prismaフィールド名 | camelCase | `projectId`, `createdAt` |
| Project ID | `prj` + 6桁連番 | `prj000001` |
| Task ID | `tsk` + 6桁連番 | `tsk000001` |
| User Code | 6桁連番 | `000001` |

## 4. テーブル定義
### 4.1 `users`
アプリケーション用ユーザー情報を管理する。
パスワードは保持しない。認証情報はSupabase Authで管理する。

| カラム名 | Prismaフィールド | 型 | 必須 | 主キー | 一意 | 備考 |
|---|---|---|---|---|---|---|
| `user_id` | `userId` | String | ○ | ○ |  | Supabase AuthのユーザーID |
| `user_code` | `userCode` | String | ○ |  | ○ | DB関数で6桁連番を自動採番 |
| `user_name` | `userName` | String | ○ |  |  | ユーザー名 |
| `user_email` | `userEmail` | String | ○ |  | ○ | メールアドレス |
| `created_at` | `createdAt` | DateTime | ○ |  |  | 作成日時 |
| `updated_at` | `updatedAt` | DateTime | ○ |  |  | 更新日時 |

制約:

- `user_email`は一意とする。
- `user_code`は一意とする。
- `password_hash`は保持しない。

### 4.2 `projects`
Project情報を管理する。

| カラム名 | Prismaフィールド | 型 | 必須 | 主キー | 外部キー | 備考 |
|---|---|---|---|---|---|---|
| `project_id` | `projectId` | String | ○ | ○ |  | `prj000001`形式で自動採番 |
| `project_name` | `projectName` | String | ○ |  |  | Project名 |
| `assignee_id` | `assigneeId` | String | ○ |  | `users.user_id` | 担当者 |
| `priority_id` | `priorityId` | String | ○ |  | `priorities.priority_id` | 優先度 |
| `status_id` | `statusId` | String | ○ |  | `statuses.status_id` | ステータス |
| `description` | `description` | String |  |  |  | 説明 |
| `start_date` | `startDate` | DateTime |  |  |  | 開始日 |
| `deadline` | `deadline` | DateTime |  |  |  | 期限日 |
| `completed_at` | `completedAt` | DateTime |  |  |  | 完了日時 |
| `created_by` | `createdBy` | String | ○ |  | `users.user_id` | 作成者 |
| `created_at` | `createdAt` | DateTime | ○ |  |  | 作成日時 |
| `updated_at` | `updatedAt` | DateTime | ○ |  |  | 更新日時 |

制約・仕様:

- `deadline`は`start_date`以降の日付とする。
- `status.is_completed = true`のステータスを設定した場合、`completed_at`に現在日時を設定する。
- `status.is_completed = false`のステータスを設定した場合、`completed_at`は`null`にする。
- 作成時の`assignee_id`と`created_by`はログイン中ユーザーの`user_id`とする。
- 関連Taskが存在するProjectはアプリケーション側で削除不可とする。

## 6. 採番設計
### 6.1 `user_code`
`public.user_code_seq`シーケンスと`public.generate_user_code()`関数を利用する。
戻り値は6桁ゼロ埋め文字列とする。

例:

```text
000001
000002
```

### 6.2 `project_id`
`public.project_id_seq`シーケンスと`public.generate_project_id()`関数を利用する。
戻り値は`prj` + 6桁ゼロ埋め文字列とする。

例:

```text
prj000001
prj000002
```

### 6.3 `task_id`
`public.task_id_seq`シーケンスと`public.generate_task_id()`関数を利用する。
戻り値は`tsk` + 6桁ゼロ埋め文字列とする。

例:

```text
tsk000001
tsk000002
```

## 7. 完了日時制御
Project / Taskのステータス変更時、変更後Statusの`is_completed`を確認する。

| `is_completed` | `completed_at` |
|---|---|
| true | 現在日時 |
| false | `null` |

この設計により、ステータス名に依存せず完了判定を行う。

## 8. 削除制御
### 8.1 Project削除
Project削除は以下の条件を満たす場合のみ許可する。

- ログイン中ユーザーがProjectの作成者である。
- 対象Projectに紐づくTaskが0件である。

関連Taskが1件以上存在する場合、アプリケーション側で削除不可エラーを返す。

### 8.2 Task削除
Task削除は、ログイン中ユーザーがTaskの作成者である場合のみ許可する。

## 9. Prisma schema
現行のPrisma schemaは以下の構成である。

```prisma
model User {
  userId    String   @id @map("user_id")
  userCode  String   @unique @default(dbgenerated("generate_user_code()")) @map("user_code")
  userName  String   @map("user_name")
  userEmail String   @unique @map("user_email")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @default(now()) @updatedAt @map("updated_at")

  assignedProjects Project[] @relation("ProjectAssignee")
  createdProjects  Project[] @relation("ProjectCreator")
  assignedTasks    Task[]    @relation("TaskAssignee")
  createdTasks     Task[]    @relation("TaskCreator")
  comments         Comment[]

  @@map("users")
}

model Project {
  projectId   String    @id @default(dbgenerated("generate_project_id()")) @map("project_id")
  projectName String    @map("project_name")
  assigneeId  String    @map("assignee_id")
  priorityId  String    @map("priority_id")
  statusId    String    @map("status_id")
  description String?
  startDate   DateTime? @map("start_date")
  deadline    DateTime?
  completedAt DateTime? @map("completed_at")
  createdBy   String    @map("created_by")
  createdAt   DateTime  @default(now()) @map("created_at")
  updatedAt   DateTime  @default(now()) @updatedAt @map("updated_at")

  assignee User      @relation("ProjectAssignee", fields: [assigneeId], references: [userId])
  creator  User      @relation("ProjectCreator", fields: [createdBy], references: [userId])
  priority Priority  @relation(fields: [priorityId], references: [priorityId])
  status   Status    @relation(fields: [statusId], references: [statusId])
  tasks    Task[]
  comments Comment[]

  @@map("projects")
}

model Task {
  taskId      String    @id @default(dbgenerated("generate_task_id()")) @map("task_id")
  projectId   String    @map("project_id")
  taskName    String    @map("task_name")
  assigneeId  String    @map("assignee_id")
  priorityId  String    @map("priority_id")
  statusId    String    @map("status_id")
  description String?
  startDate   DateTime? @map("start_date")
  deadline    DateTime?
  completedAt DateTime? @map("completed_at")
  createdBy   String    @map("created_by")
  createdAt   DateTime  @default(now()) @map("created_at")
  updatedAt   DateTime  @updatedAt @map("updated_at")

  project  Project   @relation(fields: [projectId], references: [projectId])
  assignee User      @relation("TaskAssignee", fields: [assigneeId], references: [userId])
  creator  User      @relation("TaskCreator", fields: [createdBy], references: [userId])
  priority Priority  @relation(fields: [priorityId], references: [priorityId])
  status   Status    @relation(fields: [statusId], references: [statusId])
  comments Comment[]

  @@map("tasks")
}

model Priority {
  priorityId   String   @id @default(uuid()) @map("priority_id")
  priorityName String   @map("priority_name")
  sortOrder    Int      @map("sort_order")
  createdAt    DateTime @default(now()) @map("created_at")
  updatedAt    DateTime @updatedAt @map("updated_at")

  projects Project[]
  tasks    Task[]

  @@map("priorities")
}

model Status {
  statusId    String   @id @default(uuid()) @map("status_id")
  statusName  String   @map("status_name")
  sortOrder   Int      @map("sort_order")
  isCompleted Boolean  @default(false) @map("is_completed")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  projects Project[]
  tasks    Task[]

  @@map("statuses")
}

model Comment {
  commentId String   @id @default(uuid()) @map("comment_id")
  userId    String   @map("user_id")
  content   String
  projectId String   @map("project_id")
  taskId    String?  @map("task_id")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  user    User    @relation(fields: [userId], references: [userId])
  project Project @relation(fields: [projectId], references: [projectId])
  task    Task?   @relation(fields: [taskId], references: [taskId])

  @@map("comments")
}
```

## 10. マイグレーション概要
主なマイグレーション内容は以下である。

| 内容 | 概要 |
|---|---|
| 初期テーブル作成 | users / projects / tasks / priorities / statuses / commentsを作成 |
| `task_id`採番追加 | `task_id_seq`と`generate_task_id()`を追加 |
| `user_code`追加 | `user_code_seq`と`generate_user_code()`を追加 |
| `password_hash`削除 | Supabase Auth利用に伴い`users.password_hash`を削除 |
| `project_id`採番追加 | `project_id_seq`と`generate_project_id()`を追加 |
| `updated_at` default調整 | 一部テーブルの`updated_at` defaultを調整 |
