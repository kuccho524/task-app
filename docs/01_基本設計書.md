# 基本設計書

## 1. システム概要
本システムは、Project単位でTaskを管理するタスク管理アプリである。
ユーザーはアカウント登録・ログイン後、ProjectとTaskを作成し、ステータス・優先度・開始日・期限日・説明を管理できる。

Projectには複数のTaskを紐づけることができ、Project詳細画面では関連Taskの件数、完了件数、未完了件数、進捗率を確認できる。
TaskおよびProjectは一覧画面から検索・絞り込みが可能であり、現在の検索条件も画面上に表示する。

認証はSupabase Authを利用し、アプリケーション側のユーザー情報は`public.users`テーブルで管理する。
認証情報とアプリケーション用ユーザー情報を分離し、ユーザーIDはSupabase AuthのユーザーIDと連携する。

## 2. 開発目的・背景
複数の作業やプロジェクトを扱う場合、タスクの担当者、状態、期限、完了状況を一覧で把握しにくくなる。
本アプリでは、ProjectとTaskを分けて管理し、検索・絞り込み・進捗表示により作業状況を確認しやすくすることを目的とする。

また、Next.js / TypeScript / Prisma / Supabase PostgreSQL / Supabase Authを用いたWebアプリケーション開発の学習、およびポートフォリオ作成も目的とする。

## 3. 対象ユーザー
- 個人または少人数でプロジェクト管理を行いたいユーザー
- 小規模チームでタスク管理を行うユーザー
- 業務改善やバックオフィス業務の進捗を管理したいユーザー

現時点では、ログイン済みユーザーは全Project / Taskを閲覧できる。
編集・削除は作成者のみ可能とする。
プロジェクトメンバー管理やロールベース権限制御は将来的な拡張機能とする。

## 7. 画面遷移
未ログインユーザーは`/login`または`/signup`を利用する。
`/`にアクセスした場合、未ログインであれば`/login`へ、ログイン済みであれば`/projects`へ遷移する。

ログイン後の主な遷移は以下とする。

1. `/projects`
2. `/projects/new`
3. `/projects/[projectId]`
4. `/projects/[projectId]/edit`
5. `/tasks`
6. `/tasks/new`
7. `/tasks/[taskId]`
8. `/tasks/[taskId]/edit`

Project詳細画面からTask作成画面へ遷移した場合、作成後は元のProject詳細画面へ戻る。

## 8. 各画面概要
### ユーザー登録画面
ユーザー名、メールアドレス、パスワードを入力し、Supabase Authにユーザーを登録する。
登録後はログイン画面へ遷移する。

### ログイン画面
メールアドレス、パスワードでログインする。
ログイン成功後はProject一覧画面へ遷移する。

### Project一覧画面
Projectを一覧表示する。
各ProjectにはProject ID、Project名、担当者、作成者、優先度、ステータス、関連Taskの完了数、総数、進捗率を表示する。

検索・絞り込み条件はURLクエリで保持する。

### Project作成画面
Project名、優先度、ステータス、開始日、期限日、説明を入力してProjectを作成する。
担当者と作成者はログイン中のユーザーとする。

### Project詳細画面
Projectの詳細情報、関連Task一覧、Task進捗を表示する。
作成者には編集・削除操作を表示する。
関連Taskが存在するProjectは削除できない。

### Project編集画面
作成者のみアクセスできる。
Project名、優先度、ステータス、開始日、期限日、説明を編集する。

### Task一覧画面
Taskを一覧表示する。
各TaskにはTask ID、Task名、Project、担当者、作成者、優先度、ステータス、開始日、期限日、完了日を表示する。

検索・絞り込み条件はURLクエリで保持する。

### Task作成画面
Task名、Project、優先度、ステータス、開始日、期限日、説明を入力してTaskを作成する。
Project詳細画面から遷移した場合はProjectを固定表示する。
担当者と作成者はログイン中のユーザーとする。

### Task詳細画面
Taskの詳細情報を表示する。
作成者には編集・削除操作を表示する。

### Task編集画面
作成者のみアクセスできる。
Task名、優先度、ステータス、開始日、期限日、説明を編集する。

## 10. 権限制御方針
ログインが必要なProject / Task配下の画面では、アプリ用ユーザー情報の存在を確認する。
Project / Taskの編集・削除は、対象レコードの`created_by`とログイン中ユーザーの`user_id`が一致する場合のみ許可する。

Server Actionsは直接POSTされる可能性があるため、画面表示上の制御だけでなく、Action内でも認証・認可を確認する。

## 11. テスト方針
Vitestを使用し、画面から切り出せる主要ロジックを単体テストする。
現在は以下を対象とする。

- Project進捗率計算
- Task完了件数の集計
- 編集・削除権限判定
- Project削除可否判定
- 日付フォーマット
- 開始日・期限日のバリデーション
